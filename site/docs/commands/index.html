Commands

Every command finds its corpus by looking for wherefore.json in the working directory and above it, or in WHEREFORE_ROOT. Each exits 0 when what it judges holds, 1 when it does not, and 2 for a line it cannot act on. The examples below are run on the example company, fernhollow-kettles, on every change to the engine, and must print what they say.

wherefore scan

wherefore scan PATH|URL ... [--json] [--all] [--max-pages N]

The first win, with nothing set up. Point it at what a company publishes - a built site, a docs folder, exported notes, or a live address - and it reads what a person reads there, finds every value stated in words, and reports each statement whose copies disagree, the commonest value first and every place it was said. Given several places, it tags each statement with where it came from and says what the places state in common and where any two disagree. Under the first line it says what each place contributed, and the kinds of file it saw and did not read. Source code is read for its string literals; stylesheets, style attributes and drawings for their colours, which it counts and groups by shade. A table - two values said in the same files alike - is set apart from the stale copies. --all reads files that are history by name, such as a changelog; --max-pages bounds a crawl, fifty by default. Exits 1 when any statement disagrees.

$ wherefore scan .
8 stated values in 11 files or pages; 0 statements whose copies disagree
  read  .: 6 .py, 2 .svg, 1 .md, 1 .txt, 1 .html · not read: 3 .json, 1 .gitignore
…
Every statement found says one thing everywhere it is said.

wherefore init

wherefore init [DIR]

Writes a wherefore.json that declares nothing yet, the skill where Claude Code and Codex read it, and .github/workflows/wherefore-pin.yml, the repository's own watch for the engine's releases, in the directory given or the current one. It refuses a directory that already has a wherefore.json. The skill's start.md is how the first fact is compiled; from the first build on, the skill is regenerated from the release the repository pins. The watch is the repository's from then on: every few hours it asks PyPI for the newest release, moves the pin, rebuilds, and opens a draft pull request whose checks say what the corpus still has to describe. Two settings in its header are the repository's to make.

wherefore gate

wherefore gate [--keep]
wherefore gate --restamp GROUP

The coverage gate: every tracked file must be generated during this run, authored under a rule in the inventory with a reason, or captured and stamped with what it was made from. It runs every generator twice and requires the second run to change nothing, compares every generated file with what is committed, and names each file nobody wrote and nobody claimed. The tree is put back unless --keep. --restamp GROUP records a re-made capture against its sources, for a group a person has just re-made by hand.

$ wherefore gate
15 tracked files; 4 generators
…
  ok   4 generated files, 0 differ from what is committed
  ok   the corpus settles: a second regeneration moves 0 files
…
every tracked file is classified, and every generated one was written
during this run and matches what is committed

wherefore build

wherefore build

The roll: every generator, in order, twice, compared with what is committed, and the results left in place so the diff shows exactly what a change to a fact moves. The same judgement as the gate, with the tree left as the generators wrote it.

wherefore graph

wherefore graph [--html PATH] [--json PATH|-] [--theme CSS ...] [--home URL [WORDS]]

What builds what. Runs every generator once, traces what each reads and writes, and draws one self-contained page - every source, script and file, with the lines between them - changing nothing. --json writes the same as data, or prints it with -. --theme draws it in a stylesheet's custom properties, so a corpus publishes its map in its own brand; --home puts a way back to the site on it. A corpus whose generator is itself wherefore graph is credited with that file rather than run, so a map never maps itself without end.

wherefore prove

wherefore prove [SCRIPT ...]

Runs the corpus's proofs, in place, one at a time: each plants the fault its check exists to catch, runs the check, requires it to fail naming the fault, and puts the tree back. A check nobody has seen fail is not trusted.

…
1/1 proofs held

wherefore check reach

wherefore check reach

Every fact, moved one at a time, must reach what it should: the probe nudges each fact, regenerates, and requires something a visitor receives to change. A fact that moves nothing is dead, or copied by hand into a generator; a fact a published page states reaches it by declaration. Every exemption carries a reason.

wherefore check upstream

wherefore check upstream

Every copy taken from elsewhere still matches where it was taken from, read there now. A captured group with an upstream names the address and what must still match; the check fails MOVED when the source says something else, NO LONGER SAYS when the source changed shape, and UNREACHABLE when it does not answer, unless the group says why that should not stop the corpus. It goes to the network: before a deploy, never in the gate. A corpus that configures the engine in its own scripts (entry) is read the way its gate reads it: the groups are the ones those scripts configure.

$ wherefore check upstream
nothing captured here names an upstream (1 captured groups): nothing is derived from elsewhere, or nothing says so

wherefore check palette

wherefore check palette

Every colour said anywhere is one the brand's source holds, or the file says, with a reason, whose colours they are. A colour quoted in code is text, not paint, and passes. A corpus with no brand declines the check with why.

wherefore check published

wherefore check published

Every page the company publishes but cannot build - a site on a hosted CMS - still states the source's facts, read live. A published section names each page and the facts it states as templates; the check fails SAYS OTHERWISE when the page states another value, quoting it, NOT SAID when the page states nothing like it, and UNREACHABLE when it does not answer, unless the entry says why that should not stop the corpus. Before a deploy, and on a schedule if the client wants one; never in the gate. A published page is a copy until it is built from the source.

$ wherefore check published
nothing here is published without being built: every page a visitor receives is the corpus's own

wherefore check drift

wherefore check drift

Of the files a person writes by hand - authored, or captured - which state a value in two or more of them that no source holds? A generated file restates its sources by construction; a hand-written file that states a value also stated in another, with no source behind either, is a copy nobody is keeping current. The check names each such value with the files that say it and counts them. A drift section declares how many the corpus still allows, with why, and which third-party files are not read; the check fails when more drift than that, and when fewer do it asks for the number to come down. Without a section it reports and passes: the first run says what there is to declare. The map draws the same values beside the files.

$ wherefore check drift
ok   nothing drifts: every value said by hand in two or more of 2 files is held by a source

wherefore check launch

wherefore check launch [--json]

Every thing with a stage - a feature in beta, a site launched, a roadmap item shipped - held to what its stage needs. The launch section names where each thing's stage lives, the stages in order, what each needs from then on, and what must not be said before it. The check fails a thing at a stage it does not have everything for, naming the stage and what is missing in the section's own words, and for every other thing says what the next stage still waits on. So a pull request that moves a stage is red until the stage is earned. With several ladders, each is listed under its name and a fault names its ladder. --json prints every ladder, every thing on it, its stage, and each requirement held or not, for a reader that draws it. Without a section it says so and passes.

$ wherefore check launch
ok   no launch section: nothing here waits on a stage. Declare one in wherefore.json - where each thing's stage lives, the stages in order, and what each needs

wherefore status

wherefore status [--gate] [--json] [--out PATH]

Where this repository stands, in one read: what each file is, how many values drift, where every launch stands, and which engine release it pins. It judges nothing the other commands do not; it puts their answers in one place, as a few lines or as JSON. Without --gate nothing runs: files are sorted by what wherefore.json declares, and the rest are left for the gate. With --gate the gate runs first, and its verdict and counts are in the document. --out writes the JSON to a file, which is how CI keeps it for the app to read. A repository with no wherefore.json is scanned instead: how many values it states, in how many files, and how many disagree.

$ wherefore status
fernhollow-kettles
  files    15 tracked: 10 written, 1 captured, 4 for the gate to judge
  drift    0 values said by hand twice with no source, none declared
  launch   no ladders

wherefore hook

wherefore hook install
wherefore hook pre-push

install writes a pre-push hook that rolls the corpus before a push that could move a generated document, and refuses the push if one moved. pre-push is what the installed hook runs; it is not for typing.

wherefore report

wherefore report --title TITLE WORDS ... [--from FILE] [--show | --link]

Feedback for the engine's makers - a bug, a question or a request, one topic each. It writes a title, the words as the body, the release, the corpus's shape in counts, and the output of a command given with --from; never a file's contents or a path. --show prints it and sends nothing; --link prints it with a link that opens the issue filled in, for the person to send; with neither, it opens the issue with gh, signed in, or prints the link.

$ wherefore report --title Hello the words --show
# Hello
…
--show: nothing was sent. Show the person; send it only when they say.
